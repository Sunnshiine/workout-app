# Say a set

Say a set lets the athlete log, skip, or edit a set by speaking it: holding the set card's mic, hands-free from the Action button, Siri, Shortcuts, or the rest Live Activity, or with the phone locked. Logging a set by hand, which every spoken write mirrors, is in [log-a-set.md](./log-a-set.md).

## Sub-features

- `log-speak` logs or skips the active set from a Spoken Set said while the athlete holds the card's mic, holds the written Set on the card with Saved and Clear, and shows a transcript that writes nothing in the Log button's place.
- `log-speak-handsfree` listens on the Current Session's active Set with no touch on the mic, from the Action button, Siri ("Log a Set in WorkoutTracker"), the Shortcuts app, the rest Live Activity's mic, or `workouttracker://dictate`. With the app in front the card listens, closing Settings, the Block grid, or the queue sheet first, and logs the Spoken Set once the athlete stops talking.
- `log-speak-locked` is the same request with the phone locked or the app behind another: the app listens and logs without coming forward, and reads `Listening…` then `Logged 235×5 @7` back on the Lock Screen Live Activity and the Dynamic Island (`live-activity.md`, `live-activity-dictation-readback`). The Log a Set control in Control Center, the Action button, and the rest Live Activity's mic on the Lock Screen card or the Dynamic Island run it from the Lock Screen.
- `log-speak-edit` edits a reopened logged set by holding the same mic and saying the Set, which saves it at once and closes the review.

## How to get to it (user POV)

- Hold the mic in the top right corner of the active set's card, or of a logged set's card reopened from its leaf.
- With the app in front, press the Action button set to Log a Set, say "Log a Set in WorkoutTracker", or tap the mic on the rest Live Activity's card in Notification Center pulled over the app. Each closes Settings, the Block grid, or the queue sheet, shows the Current Session, and listens on its active Set.
- With the phone locked or the app behind another, press the Action button, tap the Log a Set control in Control Center, tap the mic on the rest Live Activity, say "Log a Set in WorkoutTracker", or run Log a Set from the Shortcuts app. The phone listens without opening the app, the Live Activity reads `Listening…` then `Logged 235×5 @7` over the rest countdown, and the next unlock finds the Set logged on the card, the same rest counting down in the rest pill, and the write counted as unsynced.

## Driving it with verify.sh

Preconditions:

- SpeechAnalyzer does not run in the Simulator, so every bullet launches with `-UITEST_DICTATION "<transcript>"`, which gives the mic a transcript to hear. Each bullet launches its own run.

- **Speak.** SpeechAnalyzer does not run in the Simulator, so `-UITEST_DICTATION` gives the mic a transcript to hear. Run `verify.sh stop`, then `verify.sh launch session -UITEST_DICTATION "235 for 5 at 7"`. `find say-set-button` reads `Say Set` in the card's top right corner. To catch the press in flight, run `verify.sh axe touch -x 360 -y 504 --down`, then `verify.sh shot 07-listening`: `say-set-button` is valued `Listening` and `spoken-set-capsule` reads `235 for 5 at 7` in the Log button's frame. Run `verify.sh axe touch -x 360 -y 504 --up`, then `verify.sh shot 08-spoken`. The branch gains `Set 1, 235x5@7`, the card still reads `Set 1 of 3` with `Saved` and `clear-logged-set-menu` where the mic was, `logged-set-capsule` reads `235x5@7`, and `Sync status: 1 unsynced` appears. About four seconds later, or at once on a touch of the card (`verify.sh axe tap -x 200 -y 503` on its head, or `verify.sh axe tap -x 241 -y 642` on its values, which leaves the leaf at `Set 1, 235x5@7`, because `find rpe-7.5` says `disabled` while the card holds the Set), the card reads `Set 2 of 3` and the mic is back. Inside those four seconds, `verify.sh tap --id clear-logged-set-menu` then `verify.sh tap --label Clear` undoes the write: the leaf returns to `Set 1, 5 · RPE6`, the card shows the mic and `Log 237.5 × 5 @6`, and the header reads `Sync status: 2 unsynced`, the write and its clear. The open menu stops the four seconds, so `Clear` is still there however long the menu stays open; closing it without a Clear (`verify.sh axe tap -x 200 -y 300`) moves the card to `Set 2 of 3` at once. `verify.sh hold say-set-button` does the whole press in one step. For a transcript that writes nothing, relaunch with `-UITEST_DICTATION "100 kilos for 5"` and hold the mic: `spoken-set-capsule` reads `“100 kilos for 5”`, the card stays on `Set 1 of 3` with no `Sync status`, and a tap of the capsule brings back the Log button.
- **Speak hands-free.** The Simulator has no Action button and no Siri, and both run the same request as the app's own URL, so `xcrun simctl openurl "$SIM" workouttracker://dictate` stands in for them. Run `verify.sh stop`, then `verify.sh launch session -UITEST_DICTATION "235 for 5 at 7"`. Leave the Current Session and cover it: `verify.sh tap --id session-location-button`, `verify.sh tap --id session-tile-W1-D3`, `verify.sh tap --id session-location-button`, `verify.sh tap --id block-overview-settings-row`, then `verify.sh shot 09-covered`, which is Settings over the Block grid while W1 D3 is viewed. Run `(sleep 0.5; xcrun simctl openurl "$SIM" workouttracker://dictate) & verify.sh burst 10-dictate-link`. The first open after an install stops on a system `Open in “WorkoutTracker”?` prompt instead, so answer it with `verify.sh tap --label Open` and burst the next open. About a second after the open, Settings and the grid are gone, the stage is Week 1 Day 1 on `Set 1 of 3`, the mic is filled, and `spoken-set-capsule` reads `235 for 5 at 7`. About 1.2 s later the card logs as a held spoken write does: `Saved`, `logged-set-capsule` reading `235x5@7`, the branch's `Set 1, 235x5@7`, and `Sync status: 1 unsynced`. The listening frames last about that 1.2 s, so a plain `shot` usually misses them. `session-location-button` then reads `Open Block Overview for Week 1, Day 1`. The Shortcuts app on the Simulator lists the shortcut: run `xcrun simctl launch "$SIM" com.apple.shortcuts`, `verify.sh tap --label Continue` on a first open, `verify.sh tap --label Library` to go back to the Library, then `verify.sh tap --label WorkoutTracker`, which shows one tile, `Log a Set` with a mic. With Shortcuts in front the app is behind it, so a tap on the tile runs the next bullet's headless path, not this one.
- **Speak with the app closed.** The intent runs in the app's process whichever surface asks, and the app answers from the background when it is not in front. Run `verify.sh stop`, then `VERIFY_LIVE_ACTIVITIES=1 verify.sh launch session -UITEST_DICTATION "235 for 5 at 7"`, then `verify.sh axe button home`. Open the Shortcuts tile as above and tap it with `xcrun simctl io "$SIM" screenshot --type jpeg` running in a loop that keeps only the changed frames, or lock first with `verify.sh axe button lock` on a lane nobody else drives and run `scripts/test-sim.sh --sim "$SIM" WorkoutTrackerUITests/ActionButtonDictationUITests` with `TEST_RUNNER_WORKOUT_ACTION_BUTTON=1`, which presses the Action button itself. Within a second the Dynamic Island reads `Listening` with a mic, and the Lock Screen card reads `Back Squat`, `Listening…`, the prescription `5 reps` over `RPE6`, and the mic. About 1.2 s later it reads `Back Squat` over `Logged 235×5 @7` and `Set 1 of 3`, then the rest countdown, the bar, and `Next: Back Squat`, with the island collapsed to a check and `235×5 @7`. The app never comes forward: `xcrun simctl spawn "$SIM" log show --last 1m --predicate 'process == "WorkoutTracker"' | grep -c "Invoking LogSetByVoiceIntent.perform"` reads 1 and the Home Screen or Lock Screen stays in every frame. Unlock and run `verify.sh tap --id WorkoutTracker`, then `verify.sh shot 11-after-locked-log`: the branch holds `Set 1, 235x5@7`, the card reads `Set 2 of 3`, the rest pill at the bottom counts down the rest the locked log started (the Live Activity's countdown and the pill's agree), and `Sync status: 1 unsynced` is the write waiting for the Sheet. When the rest ends with the app still behind, the app's own rest adapter takes the activity over and it reads `Ready`.
- **Speak an edit.** Run `verify.sh stop`, then `verify.sh launch session -UITEST_OFFLINE -UITEST_DICTATION "235 for 5 at 7"`. Run `verify.sh tap --id log-active-set-button`, wait a second, then `verify.sh tap --label "Set 1, 237.5x5@6"`. The reopened card shows `logged-set-capsule` reading `237.5x5@6` and `find say-set-button` reads `Say Set` in its top right corner. Run `verify.sh hold say-set-button`, wait a second, then `verify.sh shot 04b-spoken-edit`. The leaf reads `Set 1, 235x5@7`, the review has closed to `Set 2 of 3`, the rest pill keeps counting the rest the log started, and the header goes from `Sync status: 1 unsynced` to `2 unsynced`. Reopen it with `verify.sh tap --label "Set 1, 235x5@7"`: `Saved` and `say-set-button` share the corner, so a second edit can be said too.

## Gotchas

- A request that arrives while the mic is already listening, held or hands-free, does nothing. A request is good for 10 s from its arrival (`AppEntryInbox.requestLifetime`). One the stage has not taken by then, or one still waiting when the app leaves the foreground, is dropped, so a later open never starts the mic by surprise. One that meets onboarding ends there: after `launch onboarding` and the dictate link, choosing `Replacement Training Log` lands on `Set 1 of 1` with the mic idle and `1 Set left`, however soon the tap follows the link. Onboarding that shows while a launch restores the sign-in does not end it: after `launch session -UITEST_LATE_SIGN_IN -UITEST_DICTATION "235 for 5 at 7"`, the dictate link sent during the 3 s restore logs `Set 1, 235x5@7` once the Session shows. A request with nothing to log ends where the stage is and closes nothing: on `launch completed-open-exercises`, with Settings over the Block grid, the dictate link leaves both open.
- The Log a Set control cannot run on the Simulator. Adding it to Control Center works while locked (swipe down from the top right, `Add Controls`, `Add a Control`, search `Log`), but its first render crashes the widget extension in WidgetKit's control action because the Simulator's live-entity service dies serializing any intent, a plain one with no parameters included. While it is in Control Center every `test-sim.sh` UI run fails with `Critical process WorkoutWidgets crashed`, so remove it (`Add Controls`, the minus badge) before any UI test. `verify.sh stop` uninstalls the app, which also removes the control; the Action button assignment in Settings survives an upgrade install but not an uninstall.
- Settings, Action Button, Shortcut, `Choose a Shortcut…` opens a chooser that is not in the accessibility tree, so drive it by point: the `WorkoutTracker` row, then the `Log a Set` tile. The Action button page itself is the dots under the title.
