# Log a set

Log a set lets the athlete record the active set's weight, reps, and RPE from the session stage, advances the card to the next set, marks the set on the exercise branch, and queues a write to the Sheet.

## Sub-features

- `log-adjust` changes weight with the pill steppers or the keyboard, and reps or RPE with the pickers.
- `log-submit` logs the active set and advances to the next one.
- `log-branch` shows each set as a leaf on the exercise branch with its result, and reopens a set from its leaf.
- `log-review` edits a logged set from its reopened card and saves when the review closes.
- `log-pending` queues the write and shows it as unsynced in the header.
- `log-skip` skips the active set with a long press on the log button, and clears the skip from the set's More menu.
- `log-history` opens the exercise history sheet from the last-performed line, with a volume chart.
- `log-speak` logs or skips the active set from a Spoken Set said while the athlete holds the card's mic, holds the written Set on the card with Saved and Clear, and shows a transcript that writes nothing in the Log button's place.
- `log-speak-handsfree` listens on the Current Session's active Set with no touch on the mic, from the Action button, Siri ("Log a Set in WorkoutTracker"), the Shortcuts app, the rest Live Activity's mic, or `workouttracker://dictate`. With the app in front the card listens, closing Settings, the Block grid, or the queue sheet first, and logs the Spoken Set once the athlete stops talking.
- `log-speak-locked` is the same request with the phone locked or the app behind another: the app listens and logs without coming forward, and reads `Listening…` then `Logged 235×5 @7` back on the Lock Screen Live Activity and the Dynamic Island (`live-activity.md`, `live-activity-dictation-readback`). The Log a Set control in Control Center, the Action button, and the rest Live Activity's mic on the Lock Screen card or the Dynamic Island run it from the Lock Screen.
- `log-estimate` pre-fills an RPE-prescribed Set's weight from the athlete's own Set Logs and names the basis under the weight (ADR-0018).

## How to get to it (user POV)

- Open the app with a Current Session that has pending sets. The stage shows the first pending exercise and its active set card.
- From Block Overview, tap a session tile to open that session's stage.
- From the queue sheet, tap an exercise row to jump to its active set.
- With the app in front, press the Action button set to Log a Set, say "Log a Set in WorkoutTracker", or tap the mic on the rest Live Activity in the Dynamic Island. Each closes Settings, the Block grid, or the queue sheet, shows the Current Session, and listens on its active Set.
- With the phone locked or the app behind another, press the Action button, tap the Log a Set control in Control Center, tap the mic on the rest Live Activity, say "Log a Set in WorkoutTracker", or run Log a Set from the Shortcuts app. The phone listens without opening the app, the Live Activity reads `Listening…` then `Logged 235×5 @7` over the rest countdown, and the next unlock finds the Set logged on the card, the same rest counting down in the rest pill, and the write counted as unsynced.

## Driving it with verify.sh

Preconditions:

- `verify.sh launch session -UITEST_OFFLINE` landed on Back Squat with `find session-remaining-count` reading `5 Sets left` and a `Set 1 of 3` static text. `-UITEST_OFFLINE` keeps each log queued, so the header reads `N unsynced` below. Without it the fixture sheet is reachable, so after a log the pill reads `Syncing` and then leaves, and Developer Tools lists the write as `Succeeded`.

## Gotchas

- Focusing the weight field keeps its value and typed digits append (`237.5` then `245` became `237.5245`). Backspace it clear before typing.
- A log replaces the last-performed line with this session's result, so **History** runs before **Log**. After a log, tap the new label.
- The history sheet opens at its medium detent, grabber at y 411, so the dismissing swipe starts on the dimming view above the sheet rather than on the sheet. It closes it anyway. Assert `find history-volume-toggle` exits 1 instead of reasoning from the geometry.
- Back Squat's Set 2 opens at 252.5 after Set 1 logs at 237.5 because each Set carries its own %1RM (75%, 80%) of the 315 Training Max, not because of the log. An RPE-only Set such as Bench Press does follow the log (**Estimate**). Assert the weight the card shows now, never the one before the log.
- With the keyboard up the stage drops `session-header-hud`, the branch, and the queue foot, and pins the card above the Done toolbar (DESIGN.md 5.1). One tap on the log button logs and folds the keyboard. The Exercise name and the last-performed line show only while they fit, so after a log, with the rest pill and `1 unsynced` up, expect the last-performed line without the name.
- A request that arrives while the mic is already listening, held or hands-free, does nothing. A request is good for 10 s from its arrival (`AppEntryInbox.requestLifetime`). One the stage has not taken by then, or one still waiting when the app leaves the foreground, is dropped, so a later open never starts the mic by surprise. One that meets onboarding ends there: after `launch onboarding` and the dictate link, choosing `Replacement Training Log` lands on `Set 1 of 1` with the mic idle and `1 Set left`, however soon the tap follows the link. Onboarding that shows while a launch restores the sign-in does not end it: after `launch session -UITEST_LATE_SIGN_IN -UITEST_DICTATION "235 for 5 at 7"`, the dictate link sent during the 3 s restore logs `Set 1, 235x5@7` once the Session shows. A request with nothing to log ends where the stage is and closes nothing: on `launch completed-open-exercises`, with Settings over the Block grid, the dictate link leaves both open.
- The Log a Set control cannot run on the Simulator. Adding it to Control Center works while locked (swipe down from the top right, `Add Controls`, `Add a Control`, search `Log`), but its first render crashes the widget extension in WidgetKit's control action because the Simulator's live-entity service dies serializing any intent, a plain one with no parameters included. While it is in Control Center every `test-sim.sh` UI run fails with `Critical process WorkoutWidgets crashed`, so remove it (`Add Controls`, the minus badge) before any UI test. `verify.sh stop` uninstalls the app, which also removes the control; the Action button assignment in Settings survives an upgrade install but not an uninstall.
- Settings, Action Button, Shortcut, `Choose a Shortcut…` opens a chooser that is not in the accessibility tree, so drive it by point: the `WorkoutTracker` row, then the `Log a Set` tile. The Action button page itself is the dots under the title.
- A skipped set's card has `clear-logged-set-menu`, and so does a Set held on the card after a spoken write. A reopened logged set's card has no log button and no Clear.
- The Reps and RPE rails draw about three chips and recentre on the selection, so `tap --id` on a chip outside the track exits 1 with `clipped: outside AXGroup RPE ...`. Step one chip at a time (with `rpe-6` selected the rail draws `rpe-5` through `rpe-6.5`). Exit 0 says the tap could land, not that it picked the chip, so read the log button after each tap.
