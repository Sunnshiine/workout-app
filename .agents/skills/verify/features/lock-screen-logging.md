# Lock Screen Logging

<!-- doc-symbols: not-in-tree ListCell ReduceMotionEnabled -->

During a rest the Lock Screen card shows the Set the stage's card is on: the Exercise, the weight the stage holds, the coach's Target Reps and RPE, and the Cadence and Coach Note on one line cut off with `…`. A Set is logged in two taps, Reps then RPE, without unlocking. The weight cannot change here. The second tap runs in the app's process, through the same store call as the Log capsule, so the rest restarts, the card moves on, and the write queues. A Set whose card holds no weight (a `Drop` load, a Timed Set) shows `Open to log` beside the mic. An Exercise that opens on a timed effort shows a Start in the mic's place.

## Sub-features

- `lock-screen-offer` draws the weight, the target, the queue then the guidance, and the Reps Chips (`×3` to `×7`), each a solid action green under cream as the Log capsule is, with a cream tick under each prescribed Reps, then `…`.
- `lock-screen-reps` turns the row into a back chip (`‹ ×6`) and the RPE Chips (`@6` to `@8`), with a tick under the prescribed RPE. It writes nothing.
- `lock-screen-press` logs at the tapped Reps and RPE, reads back `Logged 252.5×6 @7`, restarts the rest, then shows the next Set.
- `lock-screen-refusal` writes nothing for a press the Set no longer matches. A Set that settled leads with `That tap changed nothing` over what it holds, the Session's last Set included. Any other reason reads `Not logged` over why: `Too soon after the Reps. Tap the RPE again` for an RPE tap within a second of the row turning, after which the row still offers RPE, and `The mic is listening. Say the Set` or `The app’s mic is listening. Open to log` while a mic listens. No readback names the Block, Week, or Day.
- `lock-screen-needs-app` shows `Open to log` in place of the chips, beside the mic or the Start.
- `lock-screen-start` opens the app on an Exercise that opens on a hold, which counts down `Starts in 2`, then `Hold, N seconds left`.
- `lock-screen-open-app` opens the app from the row's `…`, for Reps no chip shows.
- `lock-screen-island` offers the same name, weight, target, guidance, and chips on the expanded Dynamic Island, and gives way as type grows. A target too long for the line shrinks, then cuts off with `…`, so the name, the weight, the mic, the queue, and every chip stay whole.

## How to get to it (user POV)

- Log a Set on the session stage and lock the phone. The card is on the Lock Screen for as long as the rest's activity runs.
- Tap a Reps Chip, then an RPE Chip. The card reads back the Set Log, then shows the next Set.
- Long press the Dynamic Island with the app behind for the same chips.

## Driving it with verify.sh

Preconditions:

- Every launch here takes `VERIFY_LIVE_ACTIVITIES=1`. `-UITEST_OFFLINE` keeps each write queued, so `Sync status` counts them.
- Run this on a simulator of your own, because locking it wedged a shared one's screenshots (`live-activity.md`, Gotchas). `verify.sh axe touch` lands where `tap` reports success and does nothing on a loaded host.
- A touch longer than about 0.2 s on `log-active-set-button` can start its hold, so give it `--delay 0.12` to `0.15`. Under load `tap --id` can report success and log nothing, so check `Sync status` after it.

## Gotchas

- A dimmed Lock Screen draws the countdown as `1:--`, and after an update it can draw a fixed stale value such as `0:37` until the screen wakes. It reads correctly about seven seconds after a touch, and it matches the stage's `rest-pill`. Trust the pill.
- A dimmed Lock Screen draws no animation, so the recorder holds the card, the readback, and the next Set as cuts. Pull Notification Center over the app to see the crossfade and a ticking countdown.
- `simctl io` cannot write under `~/Projects`, which fails with `Operation not permitted` for a screenshot and `OSStatus error -12204` for a take. Set `VERIFY_EVIDENCE` to a directory under `/tmp` for the drive, then move what you keep.
- Until `Allow` is answered the card is `@20,491 363x246`, and `Don't Allow` sits where `×6` will be, so a blind touch at y=702 refuses Live Activities for that install. Read `Allow` off the tree first. The prompt can arrive a few seconds after the first wake.
- Over Notification Center the tree also holds a `ListCell @14,0 374x219` that is not the card. Take the cell whose `y` is near the bottom, since the card's own can take seconds to list.
- The stage learns a weight changed on the app's card only through that card's mic (`mic?.shows` in `ActiveSetCard`), and the Simulator gives the card a mic only under `-UITEST_DICTATION "<transcript>"`. Without it the Lock Screen draws and logs the prefilled weight however the app's card was changed. With it, as on a phone, leaving the app redraws the card, so a change then a lock shows and logs the changed weight: `262.5 lbs` over the prefilled 252.5, then `Logged 262.5×6 @7` (measured 2026-11-08). `LockScreenPress` refuses a press only while the Lock Screen still shows a weight the app's card has since changed.
- The app launched in the background by a press after `simctl terminate` loses its `-UITEST_*` flags and reads `No Session`, so a press against a killed fixture run proves nothing.
