# Live Activity

Logging a set starts the rest timer, and the rest timer puts the countdown, the prescription and the sets left in the Dynamic Island as a Live Activity, so the athlete reads the rest with the app closed. A mic on the Lock Screen card and the expanded island presses Log a Set, which listens for the next Set without bringing the app forward when it is behind, and a Set logged by voice with the phone locked reads back on the same card and island. Developer Tools carries a Live Activity Lab that raises the same activity from a sample workout state, for design review of a variant before it ships.

## Sub-features

- `live-activity-rest-timer` raises a rest-timer activity when a set is logged, counting down outside the app.
- `live-activity-say-set` presses Log a Set from the activity's mic: with the app behind it logs the Current Session's active Set without opening the app (`log-a-set.md`, `log-speak-locked`), and with the app in front the card listens (`log-speak-handsfree`).
- `live-activity-dictation-readback` shows `Listening…` and then `Logged 235×5 @7`, `Skipped`, or `Not logged` with why, on the Lock Screen card and the island, when the Action button, a control, the activity's own mic, Siri, or Shortcuts logs a Set with the app behind (`log-a-set.md`, `log-speak-locked`). It updates the rest activity when one is running and raises one otherwise, and the readback sits over the rest the write started. A logged or skipped readback names the Exercise and Set that took the write, never the rest's next Exercise. A press the card takes while it listens, by starting its own mic, takes `Listening…` off: an activity the press raised ends, and a running rest reads as before. A press that finds no Pending Set reads `No Set left to log` under the Session (`Week 1 - Day 1`), and one with no Current Session reads `No Session` over `Open WorkoutTracker to choose a Sheet`; neither listens.
- `live-activity-lab-start` raises a prototype activity from the Lab's sample workout state.
- `live-activity-lab-update` pushes the Lab's changed sample state into the running activity.
- `live-activity-lab-end` ends the running activity from the Lab.
- `live-activity-cleanup` leaves the simulator with no activity on it for the next drive.

## How to get to it (user POV)

- Log a set on the session stage, leave the app, and read the Dynamic Island. Long press it for the whole card.
- With rest running, tap the mic on the Lock Screen card or on the expanded island. The app opens listening for the active Set.
- With the phone locked, press the Action button set to Log a Set, tap the Log a Set control, or ask Siri. The card and the island read `Listening…`, then the result, with the app still closed.
- Open the app into the `developer-tools` fixture, then Open Live Activity Lab and Start. The longer way in, from the stage through the gear at Block Overview's foot and then `settings-developer-tools-row`, is driven in `settings.md`.

## Driving it with verify.sh

Preconditions:

- Every launch in this file takes `VERIFY_LIVE_ACTIVITIES=1`, which is the only way the app requests an activity. Without it the Lab's status row reads `Live Activities disabled` and `verify.sh tap --id live-activity-lab-start-button` exits 1 saying `disabled`.
- `VERIFY_LIVE_ACTIVITIES=1 verify.sh launch session -UITEST_OFFLINE` shows the stage with `log-active-set-button` labeled `Log 237.5 × 5 @6`. `-UITEST_OFFLINE` keeps the log queued, so `rest-after-log` carries `1 unsynced`.

- **Log a set.** Run `verify.sh shot rest-before-log`, `verify.sh tap --id log-active-set-button`, `verify.sh shot rest-after-log`. The changed lines carry `AXGenericElement rest-pill Rest, 1 minute 57 seconds remaining` and relabel the button to `Log 252.5 × 5 @7`. That pill is the app's own; the activity is not in this tree.
- **Leave the app.** Run `verify.sh axe button home`, then `verify.sh shot rest-activity-home`. `verify.sh tree --all | grep WidgetRenderer-Activities` prints one `AXGroup jindo-container-view:1,client-identifier:com.apple.chrono.WidgetRenderer-Activities,element-identifier:activity:<uuid>` at `@37,14 329x37`, and the line under it reads `AXGenericElement regular.view Timer, 1:56`. Those two lines are the whole handle on a Live Activity from outside the app.
- **Open the card.** Run `verify.sh axe touch -x 201 -y 32 --down --up --delay 1.0`, which long presses the Dynamic Island, then `verify.sh shot rest-activity-expanded`. That point is the centre of the `@37,14 329x37` rect above, and the collapsed island sits there for every activity, so the same command opens the Lab's card later in this file. The element grows to `@14,14 374x123` and its line becomes `AXGroup regular.view Prescription 5 reps / RPE7, Rest, 1:51, Say Set, Rest progress, 2 sets left`, which is every field the activity carries and the mic. It collapses again after a few seconds, so shoot before driving anything else.
- **Say a Set from the Lock Screen card.** This needs the session launch above to carry `-UITEST_DICTATION "235 for 5 at 7"`, which gives the mic a transcript to hear. Pull Notification Center down with `verify.sh axe swipe --start-x 80 --start-y 2 --end-x 80 --end-y 600 --duration 0.4`, which shows the activity in its Lock Screen form without locking, then `verify.sh shot rest-activity-lock`. `verify.sh tree --all` holds `AXGroup activity-content-view` at `@14,531 374x110`, and the mic is the circle at its right end. On the first pull after an install the card carries an `Allow Live Activities from WorkoutTracker?` prompt; `verify.sh tap --label Allow` clears it and the card moves to `@14,636`, so tap 105 pt lower. Run `verify.sh burst lock-mic tap -x 350 -y 586`. The press runs Log a Set with the app behind, so the app never comes forward: the card reads `Listening…`, then `Back Squat` over `Logged 235×5 @7` and `Set 2 of 3` with `Next: Back Squat`, and `xcrun simctl spawn "$SIM" log show --last 1m --predicate 'process == "WorkoutTracker"' | grep -c "Invoking LogSetByVoiceIntent.perform"` reads 1. The listening frames are short and a burst can miss them; a `shot` a few seconds later holds the readback. Pulled down over the app in front, the same mic takes the card route instead: Notification Center stays, and swiping it away finds the card holding `Saved` with `235x5@7`. The island never shows the app's own activity while the app is in front.
- **Read a locked log back.** `log-a-set.md` **Speak with the app closed** drives it; this bullet names what the activity shows. On the Lock Screen the card reads `Back Squat` over `Listening…` in green, the prescription `5 reps` over `RPE6` right-aligned, the mic in its circle, and three empty bar segments under them. About 1.2 s later it reads `Back Squat` over `Logged 235×5 @7` and `Set 1 of 3`, with the countdown `1:59` left of a full bar (a frame caught mid-roll can read `2:59`) and `Next: Back Squat`. On an Exercise's last Set it still names that Exercise: `ActionButtonDictationUITests/testActionButtonOnAnExercisesLastSetLogsThatSetWithTheAppBehind` logs Sets 1 and 2 on the card and Set 3 locked, and the card reads `Back Squat`, `Logged 235×5 @7`, `Set 3 of 3`, and `Next: 2-3:1:0 BB RDL`. On the Session's last Set no rest follows: `testActionButtonOnTheSessionsLastSetLogsItWithTheAppBehind` presses three times from Set 3 of Back Squat, and the last readback reads `2-3:1:0 BB RDL`, `Logged 235×5 @7`, `Set 2 of 2`, and a full bar with no countdown and no `Next:`. The island collapses to a green check and `235×5 @7`. Only `Listening…` and `Logged …` take the action green; `Skipped`, `Not logged`, `No Set left to log`, and `No Session` read in the plain text colour, white on the dark card, and their island glyph and text do too (DESIGN.md, The Green Means Action Rule). When the rest runs out with the app still behind, the card reads `Ready`.
- **Leave nothing behind.** Run `verify.sh stop`. It prints `terminated pid <pid>` and then `uninstalled the app, ending any Live Activity this run started`. `verify.sh tree --all | grep WidgetRenderer-Activities` now prints nothing. Run `verify.sh shot clean-after-stop`. Its tree must hold no icon line. The check is `awk -F'\t' '$1=="AXButton" && $2=="WorkoutTracker"' clean-after-stop.tree.txt`, which prints nothing. Match the id column, not the substring, because `WorkoutTrackerUITests-Runner` also sits on the Home Screen.
- **Open the Lab.** Relaunch `VERIFY_LIVE_ACTIVITIES=1 verify.sh launch developer-tools`. Run `verify.sh tap --id developer-tools-live-activity-lab-link`, then `verify.sh shot lab-enabled`. The status rows read `Live Activities enabled` over `Prototype is stopped.`, and `verify.sh find live-activity-lab-end-button` says `off-screen` and `disabled`.
- **Start the prototype.** Run `verify.sh swipe up` once, which brings `Controls` on screen, then `verify.sh tap --id live-activity-lab-start-button`. `verify.sh tree --all | grep "Prototype is"` reads `Prototype is running.`, and `find live-activity-lab-end-button` says neither note any more. Run `verify.sh axe button home`, then `verify.sh axe touch -x 201 -y 32 --down --up --delay 1.0`, then `verify.sh shot lab-activity-expanded`. The line reads `Prescription 3-5 reps / RPE6, Rest, 1:23, Say Set, Rest progress, 2 sets left`, which is the Lab's sample state and not the session's.
- **Change what it renders.** Run `verify.sh tap --id WorkoutTracker` to reopen the app, then `verify.sh tap --id live-activity-lab-log-set-button`. `verify.sh find live-activity-lab-sets-done-stepper` reads `Sets, 4/5`. Run `verify.sh axe button home`, `verify.sh axe touch -x 201 -y 32 --down --up --delay 1.0`, and `verify.sh shot lab-activity-one-set`. The line's last field went from `2 sets left` to `1 set left`, so an in-app control reached a running activity.
- **End it from the Lab.** Run `verify.sh tap --id WorkoutTracker`, then `verify.sh tap --id live-activity-lab-end-button`. `verify.sh tree --all | grep "Prototype is"` reads `Prototype is stopped.` and `find live-activity-lab-end-button` says `disabled` again. Run `verify.sh axe button home`; `verify.sh tree --all | grep WidgetRenderer-Activities` prints nothing, so the Lab ends it without `stop`. Run `verify.sh shot lab-clean-home`, then `verify.sh stop`.
- **Proof.** Ten cells. `rest-before-log` and `rest-after-log` are the stage before and after the log, the second carrying `1 unsynced` in the header and the rest pill at the bottom. `lab-enabled` is the Lab with a green tick on its status row. `rest-activity-home` is the collapsed island, a black pill holding a green timer glyph and `1:55`, legible at that size. Its tree read `Timer, 1:56` a moment later, so the drawn digits and the label run a second apart on a live countdown. Read them as two clocks, not as a contradiction. `rest-activity-expanded`, `lab-activity-expanded` and `lab-activity-one-set` are the expanded card over the Home Screen, which it does not dim. The prescription sits at the top left, one line each and left-aligned over the bar's left edge: `5 reps` over `RPE7`, and `3-5 reps` over `RPE6` in the Lab. `Rest` sits in grey over the countdown in green in the middle, and a green progress bar runs under them with the sets left at its right end. The two Lab cells differ in that last field, `2 sets left` against `1 set left`. The right of the top row holds the mic, a green glyph in a dark green circle. `rest-activity-lock` is the Lock Screen card in Notification Center: the exercise name, the countdown, the bar and `2 sets left` on the left, the prescription right-aligned, and the mic in its circle at the right end. The Lab's Light appearance draws the same mic in dark green on the green card. Any wrapped or clipped glyph in these cells is a regression of issue 673. `clean-after-stop` is the Home Screen. It can still draw the WorkoutTracker icon for a moment after `stop`, because the Home Screen redraws an uninstall later than its tree drops it. Judge cleanup by the step's three checks, not the picture. `lab-clean-home` is the Home Screen with the icon present and nothing in the island.

## Gotchas

- Never run `verify.sh axe button lock` on a simulator anyone else will use. On one simulator it wedged the screenshot pipeline, and every later `shot` returned a frame from before the lock while the tree stayed live (issue 674). Only `xcrun simctl shutdown` then `boot` cleared it. The expanded island above is the bigger rendering, and it costs nothing. A lane simulator of your own (`scripts/lane.sh`) locked fine for the readback above, with `shot` and `xcrun simctl io screenshot` both live after the lock.
- A locked Lock Screen dims about ten seconds after the last touch, and the dimmed card draws the countdown as `1:--` with the clock flat. It is the same activity; wake the screen with the lock button and read the digits there.
- The first activity after an install puts `Allow Live Activities from WorkoutTracker?` under the card on the Lock Screen too, and `Don't Allow` sticks there as well.
- The Lock Screen asks `Allow Live Activities from WorkoutTracker?` under the first activity of each install, over `Don't Allow` and `Allow`. Answer neither. `Don't Allow` sticks to the install, and every later launch then reads `Live Activities disabled` with no flag to explain it.
- `describe-ui` answers for the frontmost app, so the activity is in the tree only while the app is not. `doctor` fails there too, saying the frontmost accessibility app is not our pid. Both are the harness, not a defect.
- A `tap --id` fired straight after `tap --id WorkoutTracker` reopens the app exited 1 twice in this drive, while `find` showed that same element enabled and on screen a second later. Re-read with `find` and repeat the tap.
- `stop` uninstalls a run that opted in, so the next `launch` reinstalls and the permission prompt comes back. A drive that never reaches `stop` leaves its activity on the simulator for whoever drives next, which is what `-UITEST_DISABLE_LIVE_ACTIVITIES` was added for (issue 657).
