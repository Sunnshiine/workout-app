# Workout App glossary: Logging

Part of the domain glossary in [CONTEXT.md](../../CONTEXT.md), which indexes every term and
defines the Program Structure, Load & Intensity, Progress, and Sync terms these lean on.

### Logging

**Set Log**: The athlete's record for a single Set, in the format `{weight}x{reps}@{RPE}` (e.g. "185x7@6"). `{weight}` is either a number in lbs or the literal "BW" for bodyweight sets (e.g. "BWx12@7"); BW is pre-filled when the coach prescribes bodyweight but always overridable with a number for weighted variations. Written into the Notes column as part of one comma-separated list of Set Logs for the Exercise. If the Exercise header Notes cell is available, that row is the Visible Writable Row; if the header Notes cell contains a Coach Note, the Coach Note is never overwritten and Set Logs move to the next Visible Writable Row in the same Session. Avoid: actual load, log entry.

**Unstructured Set Log**: Non-empty athlete text for a Set that marks that Set Logged but does not parse as a structured Set Log. It is Set-level completion evidence, distinct from a Legacy Log, and may be overwritten by a structured Set Log when the athlete corrects it. Avoid: completed from sheet, already logged.

**Load Suggestion**: A calculated weight hint pre-filled in the set weight input. Three sources, the coach's explicit numbers first: (1) "Drop X%" — computed from the previous set's logged weight once the athlete has logged it; (2) "%1RM" — computed from the Block's Training Max; (3) an RPE target ("RPE8" for 5 Reps) — computed from the athlete's own Set Logs through the RPE Table, and carrying its Load Basis, which Developer Tools can show on the card. Always overridable. Avoid: recommended weight, auto-fill.

**RPE Table**: The curve that relates a Set's reps and RPE to a share of the athlete's Estimated Single. One RPE point below 10 is one rep in reserve, so a Set of 5 @8 and a Set of 7 @10 sit at the same point of the curve. Covers reps 1 to 12 at RPE 6 to 10, and a Set outside that range estimates nothing. Avoid: RPE chart, percentage chart.

**Estimated Single**: The weight one structured Set Log implies the athlete could lift for a single rep at RPE 10 that day, read through the RPE Table. Used only inside a Load Suggestion for an RPE target, and never shown, stored, or written to the Sheet. Distinct from Training Max, which the coach derives and the estimate never reads. Avoid: 1RM, e1RM, max, Training Max.

**Load Basis**: The one Set Log a Load Suggestion for an RPE target was computed from, and where it was logged. It is the nearest earlier Set of the same Exercise in the Viewed Session whose Set Log the RPE Table covers ("from Set 1 today"). Otherwise it is the highest-RPE Set Log of the Exercise's most recent Exercise History entry from another Session, named by Session Address ("from 315x5@7 · W1 D2"), with the Block added when the entry is from another Block ("from 195x5@8 · Block 26 W4 D1"), and the entry's own entered name added when the Last Performed ladder, run without the Viewed Session, matched it at Movement level ("from 195x5@8 · W1 D2 as “Comp Bench Press”"). The Last Performed line runs the same ladder with the Viewed Session included, so mid-Session the two lines can name different entries. Today's Set Log always wins over history, so a first Set that ran harder than prescribed lowers the next. Avoid: source, reference set, anchor.

**Last Set RPE**: The RPE the athlete reports for the final Set of an Exercise. Stored in column I — the app extracts it from the last Set Log and writes it there automatically. It mirrors that one Set Log and holds no state of its own, so it is cleared whenever the final Set stops being Logged, by a Skip as well as by a delete. No parser path reads column I back into the model, so a stale value is invisible in the app and visible only to the coach. Avoid: actual RPE.

**Coach Note**: Instruction-shaped text the coach places in the Notes column (J) on the Exercise header row — e.g. "Start w/ 10 sec hold, proceed to rep range" or "Superset w/...". Read-only to the athlete and never overwritten by the app. When the Exercise header Notes cell contains a Coach Note, Set Logs move to the next Visible Writable Row in the same Session.

**Legacy Log**: Result-shaped athlete text from older exercise-level logging habits — e.g. "70@10, 55", "55x8, 60x7@9.5", or "70, 80, 90x6". Counts all prescribed Sets for that Exercise as complete and can serve as Last Performed evidence when current Set Logs are absent; completion summaries and history display the raw entered text. It is not a Coach Note and is not a current structured Set Log. Avoid: legacy anchor result, current log.

**Header Notes Role**: What occupies one Notes cell, decided once from the cell value and the number of Sets that cell is prescribed to carry. It is exactly one of three things: that Exercise's or Prescription Line's Set Logs (an empty cell, a single Set Log, or a comma list no longer than the Set count), a Coach Note, or a Legacy Log. The three are mutually exclusive, so a cell the app itself wrote as Set Logs can never also surface as coach prose. Avoid: header type, notes kind, protected header.

**Completion Evidence**: What an Exercise's completion is read from. It is either the Exercise's Set-level Set Logs in Set order or its Legacy Log. A Set counts as Set-level evidence when the athlete logged it, whether the text parsed as a Set Log or stands as an Unstructured Set Log. A Skipped Set does not count, because a skip records that the athlete did not perform the Set. The Legacy Log is the fallback, used only when the Exercise bears no Set-level evidence at all. One logged Set supersedes it, and the Sets it no longer speaks for stay Pending. Avoid: completion source, evidence log, log precedence.

**Set State**: The status of a single Set — Pending (not yet logged or skipped), Logged (a Set Log or Unstructured Set Log exists for that Set), or Skipped (athlete explicitly marked that Set skipped; "skip" written into the Exercise's Set Log list so the coach can see it). Skipping is Set-level; an Exercise is complete when all prescribed Sets are Logged or Skipped, or when a Legacy Log completes the Exercise. Avoid: done, missed, incomplete.

**Superset**: An athlete-created pairing of exactly two Exercises in the Current Session, used to alternate between their remaining Pending Sets while both Exercises still have pending work. Default Superset progression alternates by each Exercise's pending Set order, but the athlete can manually focus either Exercise's next Pending Set inside the Superset. Logged and Skipped Sets do not participate in Superset progression. Only Exercises with at least one Pending Set can enter a Superset. A Superset may be created before either Exercise is in focus; it becomes active when normal Set progression reaches either paired Exercise, and dissolves either when manually dismissed or as soon as either Exercise has no Pending Sets. Once dissolved, a Superset must be created again intentionally. Each Exercise can belong to at most one Superset, and each Set remains part of its original Exercise. Avoid: block, group, circuit, paired workout.

**Open Exercise**: An Exercise with at least one Pending Set in any Session belonging to the Current Week. Surfaced by the app as a makeup queue. Abandoned (no longer surfaced) the moment the athlete starts any Session in the next Week — makeups only exist within a week boundary. Avoid: deferred exercise, incomplete set.

**Makeup Day**: An informal extra gym visit within the Current Week, used to complete Open Exercises from Days 1–N. Not a distinct Session column in the sheet — makeup exercises are logged back into their original Day's column. Avoid: bonus day, extra session.

**Cadence**: The tempo prefix on an exercise name encoding eccentric, pause, and concentric durations (e.g. "2-3:1:0" in "2-3:1:0 BB RDL"). Prescribed by the coach; displayed in the UI but stripped for fallback index lookups. Avoid: tempo.

**Entered Name**: An Exercise's name exactly as the coach wrote it in the name cell, Cadence prefix included (e.g. "2-3:1:0 BB RDL"). It is the Exercise's identity: an Exercise Reference names the Exercise by it, and Exercise History dedups on it (ADR-0012). Never shown to the athlete as the name. Avoid: full name, raw name.

**Exercise Reference**: Which Exercise of a Session a Set belongs to, as the Sheet addresses it: its Entered Name plus how many Exercises above it in the Session share that name. A coach can name two Exercises in one Session the same, as a top single and its back-off Sets both `Back Squat`, so the Entered Name alone can match several rows. A queued write persists one and the Sheet write finds its row by it (ADR-0006), and a conflict names any Exercise past the first of its name by its place among them ("Back Squat number 2" for the second). Avoid: exercise ordinal, exercise index, exercise key.

**Base Name**: An Exercise's Entered Name with the Cadence prefix removed (e.g. "BB RDL"). What the athlete reads as the Exercise's name, so the coach's tempo notation never reads as part of it. The second Last Performed tier matches by it, and the Exercise History fill counts by it. Two Exercises with the same Base Name under different Cadences are still two Exercises.

**Last Performed**: The most recent completion evidence for a given Exercise across all past Sessions — every logged Set Log of that performance in Set order (e.g. "70x8@8, 75x8@9.5"), or the Legacy Log when no Set-level Set Log exists. Showing the whole previous Exercise (not just its final Set) lets the athlete read how it progressed Set to Set and choose a starting weight. Displayed as a reference when the athlete views that Exercise in the Current Session; Legacy Logs are shown as their raw entered text rather than normalized into structured Set Log format. Lookup is a three-tier ladder, most comparable first: (1) match full exercise name including Cadence; (2) if no result, strip Cadence and match base name; (3) if still no result, match at Movement level (ADR-0013) and label the line with the matched entry's own entered name (as "…") so the spelling difference stays visible. If any occurrence was Skipped, continue backwards until completion evidence is found. Backed by a local index so the lookup is instant. Avoid: personal record, previous result, history.

**Exercise History**: A view of an Exercise's prior entries across Sessions — an **entry** is that Exercise as logged in one past Session, shown as its Set Logs in Set order or its Legacy Log / Unstructured Set Logs as raw entered text. Shows the last ~5 entries, collected at Movement level so spelling variants and Cadence prefixes never silo history; entries display in strict recency order and annotate themselves with their own entered name only when it differs beyond case from the viewed Exercise's. Only completion evidence earns an entry — fully Skipped occurrences are omitted. Opened mid-Session by tapping the Last Performed line. Backed by the append-only `exercise_history` index (ADR-0012). Distinct from Last Performed, which is only the single most recent entry. Avoid: Last Performed, previous result, performance history.

**Session Coordinate**: Which Session of which Block — Block tab · Session Address, written `Block 27 · W1 D1`. Queued writes hold one as recorded when the write was queued. Persisted as an Exercise History entry's `source` and used as the append-only index's dedup key (ADR-0012), so it is an identity rather than a label: the sheet's Block header and its `W1 D1` gutter are projections of the coordinate, and changing how a Session reads on screen never re-keys a stored entry. Superset pairing, the rest Live Activity, and the Session screen's focus and Dictation match a Session across a re-parse by this coordinate, so a Detached Session matches nothing. Unrelated to the Superset pairing origin, also called a source in `Session/`. Avoid: source, source label, session string.

**Detached Session**: A Session the app was still holding when a sync replaced the cached Block, so no Block holds it any more and it knows only its Day number. It has no Session Coordinate and no Session Address: navigation, the Current Session Pin, and the write path refuse it, and a holder re-resolves it by the Session Coordinate or Session Address it captured while the Session was live. Avoid: weekless, missing week, Week 0, None.

**Exercise History fill**: The job each sync starts to make Exercise History complete — it reads the Sheet's historical Block tabs newest-first into the `exercise_history` index until every Exercise in the current Block, counted by Cadence-stripped base name, holds the ~5 entries Exercise History shows, or the Block tabs run out. A tab it cannot read halts the fill rather than being skipped, because a hole in the middle corrupts the coverage count; the deepest tab it did read is kept as a cursor, so the next sync resumes from just below it instead of starting over (ADR-0012). Avoid: backfill, Last Performed backfill.

**Movement**: The cross-Session exercise identity Exercise History collects — what two Exercises share when, after stripping Cadence and canonicalizing the name (case, punctuation, whitespace, known abbreviations), their names fuzzy-match (normalized edit distance ≥ 0.8, anchor-relative to the viewed Exercise, biased to over-match; ADR-0013). Coarser than Exercise: "0:2:0 Hamstring Curl" and "Hamstring Curl" are one Movement, as are "Standing Calve Raises" and "Standing Calf Raise"; "Paused Bench Press" and "Bench Press" are two. A choice Exercise, one name offering options joined by the word "or", is the same Movement as each of its options, with words written once shared across them: "Incline Machine or DB Bench Press" covers "Incline DB Bench Press", and "Leg Press or Hack Squat" covers "Hack Squat". Avoid: exercise group, canonical exercise.

**Opening Hold**: A hold at the start of each Set of an Exercise, prescribed in its Coach Note as a duration written beside "hold" or "iso" ("Start w/ 10 sec hold, proceed to rep range" holds 10 s; "Iso 10s at the top" too). Read from the Coach Note each time and never stored. A duration the note ties to each rep, to the time between Sets, or to the last rep is none ("rest 90 sec", "10 sec hold after your final rep"), and a Cadence is never a duration. When a note writes several, the first wins. Avoid: isometric hold, pre-hold, hold time.

**Timed Set**: A Set whose Prescribed Reps is a duration rather than a rep count ("40 sec", "0:45", "30-45 s", low end first). It has no rep target, so its Load Suggestion is what it was when the app read the cell as uninterpreted text. Avoid: duration set, time-based set.

**Timed Effort**: The one timed part of a Set the Set card counts: the Exercise's Opening Hold, else the Set's own Timed Set duration, else none. Offered on every Pending Set the card logs. Avoid: timed hold.

**Lead-in**: The five seconds an Effort Countdown counts down out loud before the Timed Effort begins, so the athlete who tapped has time to get their hands on the machine. Fixed, with no setting (ADR-0023). Avoid: get-ready, prep time.

**Effort Countdown**: The count one tap on the Set card starts: the Lead-in, then the Timed Effort's seconds, each cue spoken and felt so an athlete with their hands on the machine follows it without looking ("5" to "1", "Hold" or "Go", the last three seconds, then "Done" or "Time"). Starting one ends a rest still running. Logging, skipping, or moving the card off its Set, pressing the mic, leaving the Session screen, or a tap on it ends it. Never stored and never written to the Sheet (ADR-0023). Avoid: hold timer, interval timer.
