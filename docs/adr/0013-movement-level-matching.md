# Movement-level matching for Exercise History

Amends [ADR-0012](0012-exercise-history-append-only-index.md), which deferred the matching rules to this decision.

The coach spells the same movement differently across Blocks — "Standing Calve Raises" / "Standing Calf Raise", "Comp BP" / "Competition Bench Press" — and Cadence prefixes fork names further. Exact-string matching (the only matching in the codebase today) silos one movement's history into several lists, each too short to read a trajectory from. The athlete thinks in Movements and reads history to pick a starting weight, so Exercise History must collect entries per **Movement**: the cross-Session identity that survives Cadence and spelling noise.

Two Exercises are the same Movement when their canonicalized names fuzzy-match. Canonicalization is deterministic: strip the Cadence prefix via the existing `splitCadence`, lowercase, map punctuation to spaces, collapse whitespace, then expand tokens through a small abbreviation table (`bp → bench press`, `comp → competition`, `db → dumbbell`, `bb → barbell`, `bw → bodyweight`; `rdl` stays, it is never spelled out). Fuzzy equivalence is normalized Levenshtein similarity — `1 − distance/max(length)` — at threshold **0.8**, hand-rolled (~30 lines), no dependency.

Modifier words split Movements: "Paused Bench Press" and "Bench Press" are programmed at genuinely different loads, and lumping them puts misleading weights at the top of a list whose primary reading is "pick my starting weight". At θ = 0.8 the threshold splits them naturally (0.61) while merging typos (0.86) and plurals (0.93). One over-match is accepted with eyes open: long names differing in a short modifier token — "incline dumbbell bench press" vs "decline dumbbell bench press" (0.93) — merge. No token-level guard can fix this: "incline/decline" (0.71 token similarity) and "calve/calf" (0.60) are indistinguishable to edit distance at token scale, so any guard that splits the former also splits the typo that must merge. This is the standing over-match preference — fewer silos, split when concrete cases surface — and the abbreviation table is the escape hatch: it can grow explicit never-merge pairs as a data fix, no algorithm change.

Matching runs at **query time, anchor-relative** to the viewed Exercise: canonicalize its base name, fuzzy-compare against the distinct base names on device (a few hundred at most — microseconds), and pull entries for the matching set. No movement key is persisted and no clustering is ever computed; pairwise similarity is not transitive, but anchor-relative matching never needs it to be. Rule changes (a new abbreviation, a threshold tweak) apply instantly to all existing rows with no migration. Canonicalization may be memoized in memory.

**Last Performed** becomes a three-tier ladder, most comparable first: (1) exact full name including Cadence, (2) exact base name, (3) Movement level. Tiers 1–2 are byte-identical to today's behavior; tier 3 fires only where the line would otherwise be blank — the misspelled-exercise case where history exists on device but the tappable entry point would vanish. A tier-3 line labels itself with the matched entry's own entered name (*as "Standing Calve Raises"*). The history sheet behind the tap always matches at Movement level regardless of which tier produced the line, so the line's entry may differ from the sheet's top row: the line is "you, on this exact prescription"; the sheet is "this movement lately".

Inside the history sheet, entries keep strict recency order under their Block headers, and an entry annotates itself with its own entered name — same muted *as "…"* vocabulary as the tier-3 line — only when its base name differs beyond case from the viewed Exercise's. The common case stays one clean line per entry, exactly as prototyped; the lumping is visible precisely where it happened, including deliberate merges like "Comp BP".

**Considered alternatives:** Token-overlap scoring (Jaccard / token-set ratio) — rejected; "Bench Press" ⊂ "Paused Bench Press" scores near-perfect, merging exactly the modifier class that must split. A fuzzy-matching library (Fuse-swift) — rejected; Bitap-style substring search solves a different problem, and a dependency buys nothing over 30 lines of Levenshtein. An ingest-time canonical `movementKey` column — rejected; fuzzy equivalence is pairwise, not a stable hash, and every rule change would strand already-stamped rows behind a re-derivation migration.
