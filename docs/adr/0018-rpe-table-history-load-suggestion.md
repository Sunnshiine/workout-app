# History Load Suggestion through the RPE Table

The commonest prescription is an RPE target, such as `RPE8` for 5 Reps, and the Set card pre-filled no weight for it. A **History Load Suggestion** is a Load Suggestion for an RPE target, computed from the athlete's own Set Logs. This records how it computes the weight and which Set Log it computes from.

The **RPE Table** is the RTS chart, which gives the share of a single at RPE 10 for each pair of reps and RPE. One RPE point below 10 is one rep in reserve, and the chart's rows are exact one-point shifts of each other. We store it without loss as one curve over effective reps (reps plus reps in reserve) in half steps, 31 values from 100% at 1 to 57.4% at 16. The supported range is the chart's own, reps 1 to 12 and RPE 6 to 10. The chart has no RPE 5 column, and a rating that far from failure is too loose to estimate from, so a basis or target outside the range gets no suggestion instead of an extrapolated number.

The basis weight divided by its share is the **Estimated Single**. The Estimated Single times the target's share, rounded to the engine's existing 2.5 lb plate increment, is the suggestion. For `315x5@7` toward a `5 @8` target, effective reps 8 is 78.6%, so the Estimated Single is 400.8, and effective reps 7 is 81.1%, which gives 325. The Estimated Single is never shown, stored, or written to the Sheet.

The coach's numbers come first. Precedence is BW, then Drop from the previous Set's weight, then %1RM with a Training Max, then the History Load Suggestion. The estimate never reads the Training Max, so the pre-fill always agrees with the Set Log the card names as its basis.

The basis is the freshest usable Set Log, meaning structured, in pounds, with reps and RPE inside the table. The nearest earlier Set of the same Exercise in the Viewed Session comes first, and nearer Sets that are not usable are passed over. Any usable Set today beats history, so a first Set that ran harder than prescribed lowers the next. Otherwise the basis comes from the newest Exercise History entry the Last Performed ladder finds ([ADR-0013](0013-movement-level-matching.md)), outside the Set's own Session, which enters the index as soon as one of its Sets is logged. Within that entry the basis is the highest-RPE usable Set Log, ties going to the later one. Ratings are most accurate near failure, and every Set of the Exercise gets the same basis. If that entry holds no usable Set Log there is no suggestion, and the lookup does not walk further back.

An entry stores only its display text, and a Legacy Log ([ADR-0005](0005-legacy-logs.md)) such as `55x8, 60x7@9.5` holds tokens that parse. So the Legacy rule runs at read time. An entry can supply a basis only when every token is a structured Set Log or `skip`. A persisted `isLegacyLog` attribute would cost a SwiftData migration and would read false on every past-Block row already on device, because sync re-extracts only the current Block's tab and the Exercise History fill stops once it holds enough entries. The read-time rule accepts one risk: a Legacy Log whose every token is a well-formed Set Log reads as Set Logs.

The target is the Reps cell when it holds one number from 1 to 12. A range such as `8-10` or `7 - 8`, both ends in 1 to 12, targets its midpoint on the half-step grid (9 and 7.5), which errs least in either direction. AMRAP, `5+`, timed Sets, and other Reps text get no suggestion. The card names the basis under the weight in the athlete's notation, such as `from 315x5@7 · W1 D2` or `from Set 1 today`, so the athlete can judge the number and overrule it (DESIGN.md 5.2).

**Considered alternatives:** Epley or Brzycki formulas were rejected because they ignore RPE, so `225x5@6` and `225x5@9` would imply the same single. A persisted Estimated Single trend was rejected as a second store that drifts from the Sheet ([ADR-0001](0001-sheet-as-backend-local-first.md)), bought with a migration. Reading the Training Max was rejected because it is the coach's per-Block number and does not move with the athlete's latest Sets. The token nearest the target in reps was rejected because it names a different Set Log for each Set of one Exercise. The last token was rejected because a back-off Set would outrank a top Set at RPE 9. The top of a rep range was rejected as one coach's reading, light whenever the coach means the low end. A persisted `isLegacyLog` was rejected for the migration and the past-Block default above.
