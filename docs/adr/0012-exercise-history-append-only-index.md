# Exercise History: append-only entry index

Supersedes [ADR-0002](0002-last-performed-local-index.md).

Athletes need to open an Exercise's history mid-Session — the last ~5 entries, read in seconds at the rack, offline. ADR-0002's `last_performed` index cannot serve this: `LastPerformedIndex.ingest` overwrites the single row per exercise name, destroying every older entry on each sync.

We replace the single-entry index with one append-only `exercise_history` table. Each row is an **entry** — an Exercise as logged in one past Session: display string (Set Logs in Set order, or Legacy Log / Unstructured Set Log text as entered), date, `source` (tab·week·day), full name, and base name. `source` is the dedup key, because dates degrade to `.distantPast` when unparseable. Existing `last_performed` rows seed the table. **Last Performed** becomes a query over these rows — most recent entry via the existing two-tier lookup (full name including Cadence, then base name) — while Exercise History queries the same rows wider, at movement level (matching rules: see the Exercise History spec). There is no second store and no dual write.

The table is filled at sync-time by extending the existing lazy backfill (the `launchLastPerformedBackfill` seam and its observer). The stopping rule is coverage-based: scan Block tabs backwards until every current-Block Exercise has at least 5 entries, counted per Cadence-stripped base name, or tabs are exhausted — typically a 2–3 tab reach. Coverage counting at base-name level may occasionally over-fetch a tab relative to movement-level matching; that errs toward more data on device, never less. After the initial fill, ordinary sync appends entries as the athlete logs. Reads are fully offline.

Fill robustness lives in the Sheets client, independent of storage: no artificial throttle (sequential single-tab GETs at this reach never approach the 60 reads/min quota); exponential backoff on 429/5xx (1s, 2s, 4s, 8s, then the tab is failed); on a failed tab the fill halts and resumes on the next sync from a persisted deepest-ingested-tab cursor — never a silent skip, because a hole in the middle corrupts the coverage count and triggers pointless deeper scanning. Re-ingesting a tab is idempotent via `source` dedup, so the cursor is advisory. The fill publishes per-tab progress, and the UI surfaces it as a visible, playful progress affordance rather than filling silently.

The evidence function is extended so Unstructured Set Logs count as completion evidence, as the glossary already promises — an Exercise completed only through Unstructured Set Logs earns an entry, rendered as its raw entered text. Fully Skipped occurrences earn no entry.

**Considered alternatives:** On-demand backwards scan at tap time — rejected; it is the approach ADR-0002 already rejected, and the gym-floor context makes offline binding. Persisting old Blocks for per-Set structured fidelity — rejected; the validated digest view renders one line of text per entry and consumes no queryable Set structure, while the change would break the single-Block invariant across `WorkoutStore.reload`, `SyncCoordinator.replacePersistedBlock`, and bootstrap. A CloudKit tier — rejected; it would mirror a re-derivable ≲1 MB index at real infrastructure cost (see the Exercise History architecture research).
