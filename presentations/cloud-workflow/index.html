This is the whole talk on one slide. The top lane is me. The bottom lane is the factory: agents in GitHub Actions, started by labels.

I choose the feature. I plan it with an agent in Wayfinder sessions, one question at a time. I explore designs: HTML prototypes in the browser, and phone builds I hold in my hand.

Then the decisions become tickets, and the tickets go down to the factory. It implements each ticket, reviews the code, opens a ready PR, and builds to TestFlight with the testflight label. Today the factory sends the build to my phone; in July I applied that label myself.

Two things come back up: a PR and a build on my phone. I judge both. That is the line. Automate the building. Keep the deciding.

Why? The ticket was right. It said weight leads at 46 points, centered. The build drew a small Weight label above a value around 20 points.

Give agents the artifact
they need to judge.

Pixels for UI.

If you take one thing from this talk: give agents the artifact they need to judge.

My first agents had the ticket, the tokens, and the compiler. They didn't have the pixels. The ticket was right and the code compiled, and it still shipped the old screen in new paint.

For UI, the artifact is pixels: a simulator, screenshots, and the accepted prototypes to compare against. Once the agent had those, the second try matched what I picked.

[ledger on #467; #469; #485; #505]

Next: a codebase agents can change correctly.

What's next. I want an agent to pick up a story and produce an implementation I trust. That needs a codebase agents can change correctly.

Four moves. Delete dead code, one-caller wrappers, and tests that pass whatever the code does; three PRs did that on October 4. Make modules deeper, so there is less surface to get wrong. Turn standards into lint rules, so a rule fails the build instead of living in a doc; four of them have run at error since late September. And every time an agent makes a mistake, turn it into a check.
